== STEP 7: first run attempt (found a bug in my own harness, recorded for honesty) ==
$ .\repro.exe -mode=buggy -calls=5        (healthy: leaked 5 goroutines)
$ run.ps1 with `& $exe -mode=$mode -calls=5`
RESULT: the flag value arrived as the literal string "$mode", so BOTH the "buggy" and the "fixed"
runs executed the buggy code path — every run said "BLOCKING REPRODUCED".
Diagnosis: PowerShell did not expand the variable inside the single token `-mode=$mode` when
passed to a native executable.
FIX applied to run.ps1: pass the arguments as separate tokens: `& $exe ("-mode=" + $mode) "-calls=5"`.
Re-verified manually: `.repro.exe -mode=fixed -calls=5` -> "[mode=fixed] goroutines = 1" (no leak).
This mistake is kept in the log because it is exactly the kind of harness bug that silently
falsifies an experiment (a "fixed" mode that never ran).
